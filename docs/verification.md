## 一次失败及修正

首个真实任务校验成功后，客户端曾因签名返回 HTTP 地址而在文件发送前停止。再次从 check 开始时，服务器返回二维码已使用。

随后客户端增加了检查点保存：校验前确认状态路径可写，校验成功后立即保存 JWT/captureId，重试复用任务。OSS 地址采用同一主机的 HTTPS 服务，新的完整上传得到 HTTP 201。

检查点无法消除所有分布式不确定性：若服务器已消费二维码但连接在响应到达前中断，客户端拿不到凭证，只能停止重扫并要求刷新二维码。

## 复现边界

- 文件进入 OSS、业务处理 PASS、采集任务确认、报名网页选用照片分别是不同状态。
- 当前最大像素、其他图片编码以及不同任务/背景模式的策略没有经过穷举验证。
- 原始业务 DEX 中仍存在 native/虚拟化方法，没有宣称完整还原 App。
- 本次仓库整理沿用已验证客户端，没有为发布准备而再次发起采集或照片上传。
